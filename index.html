Variante 1 · Overlay über bestehende Buttons

Du hast bereits einen "Termin buchen"-Button auf der Seite (wie oben im Hero oder in der Info-Card) und möchtest, dass ein Klick darauf das Widget als Overlay öffnet. Ein einzelner Script-Tag plus ein onclick-Handler reichen.

Live
So bindest du das ein
<!-- Einmal im <head> oder vor </body> --> <script src="https://sbo-booking-widget.netlify.app/booking-widget.umd.js"></script> <!-- Beliebiger Button auf der Seite --> <button onclick="BookingWidget.open({ dealerId: 'senker' })"> Termin buchen </button>

Das UMD-Bundle registriert window.BookingWidget. Funktioniert auf jeder Seite, unabhängig vom CMS oder Framework.

import { BookingWidget } from '@dealer/booking-widget' function TerminButton() { const [open, setOpen] = useState(false) return ( <> <button onClick={() => setOpen(true)}>Termin buchen</button> <BookingWidget mode="overlay" dealerId="senker" open={open} onClose={() => setOpen(false)} /> </> ) }

Variante 2 · Fertiger CTA-Button

Wenn du keinen eigenen Button stylen möchtest, kannst du den vorgefertigten Pill-CTA verwenden. Er bringt sein gesamtes Styling inline mit, funktioniert in jedem CSS-Kontext und öffnet beim Klick automatisch das Overlay.

Live
So bindest du das ein
import { BookingCtaButton } from '@dealer/booking-widget' <BookingCtaButton dealerId="senker" /> // Optional anpassbar: <BookingCtaButton dealerId="senker" title="Service-Termin reservieren" subtitle="In 60 Sekunden online" bookingOptions={{ onBooked: (id) => track(id) }} />

Der CTA-Button ist eine React-Komponente und damit für React-/Next.js-Seiten gedacht. Für reine HTML-Seiten nutze stattdessen den Script-Tag mit eigenem Button-Styling (siehe Variante 1).

<!-- Variante für Nicht-React-Seiten: Eigener Button im CTA-Stil --> <script src="https://sbo-booking-widget.netlify.app/booking-widget.umd.js"></script> <button class="sbo-cta" onclick="BookingWidget.open({ dealerId: 'senker' })"> Werkstatt-Termin buchen </button>

Sag Bescheid, wenn du eine vanilla-HTML/CSS-Version mit Icon + Subtitle brauchst — ich liefere einen reinen HTML+CSS-Snippet ohne React-Dependency nach.

Variante 3 · Inline-Einbettung

Statt eines Overlays kann das Widget auch direkt in den Seitenfluss eingebettet werden — als statische Komponente, die sofort sichtbar ist. State und Persistenz bleiben identisch zum Overlay-Modus.

Live
So bindest du das ein
<!-- Script einmalig auf der Seite einbinden --> <script type="module" src="https://sbo-booking-widget.netlify.app/booking-widget.es.js"></script> <!-- Beliebig oft auf der Seite verwendbar --> <booking-widget dealer-id="senker" mode="inline" language="de" theme="vw" <!-- optional: "neutral" | "vw" --> ></booking-widget>

Custom Element: das Tag <booking-widget> wird vom Bundle automatisch registriert. Alles läuft im Shadow DOM, dein Seiten-CSS bleibt unberührt.

import { BookingWidget } from '@dealer/booking-widget' function ServicePage() { return ( <BookingWidget mode="inline" dealerId="senker" language="de" theme="vw" /> ) }

Variante 4 · Prefill & URL-Parameter

Daten von der Trägerseite ins Widget durchreichen — typische Anwendungen: die Trägerseite hat eine carlog-Session aufgelöst und kennt die Kundendaten, oder eine E-Mail-Einladung enthält Link-Parameter mit vorausgewählten Services und einem Termin. Reihenfolge: persistierter Draft < URL-Params < explizites prefill-Prop.

Live ausprobieren
… oder URL mit ?bw_*-Parametern in einem neuen Tab öffnen
So bindest du das ein
// Trägerseite hat carlog-Session aufgelöst und kennt den Kunden. <BookingWidget dealerId="senker" theme="vw" prefill={{ customer: { email: 'max@example.com', firstName: 'Max' }, vehicle: { brand: 'vw', model: 'polo' }, services: { selected: ['raederwechsel', 'oelwechsel'] }, step: 3, }} />

Übergebene Felder überschreiben den persistierten Draft. Wenn customer.email gesetzt ist, blendet das Widget den carlog-Login-Banner aus und zeigt stattdessen "Daten übernommen".

<!-- Prefill als JSON-Attribut --> <booking-widget dealer-id="senker" theme="vw" prefill='{"customer":{"email":"max@example.com"},"services":{"selected":["raederwechsel"]}}' ></booking-widget> // Oder via JS-API für das Overlay: BookingWidget.open({ dealerId: 'senker', theme: 'vw', prefill: { customer: { email: 'max@example.com' } } })
// E-Mail-Versand baut einen Link mit bw_*-Parametern: https://senker.at/service-buchen ?bw_email=max@example.com &bw_first_name=Max &bw_brand=vw &bw_model=polo &bw_services=raederwechsel,oelwechsel &bw_date=2026-11-08 &bw_time=10:00 &bw_step=3 // Das Widget liest sie automatisch beim Mount. // Deaktivieren: readUrlParams={false} // Eigener Präfix: urlParamPrefix="senker_"

Unterstützte Parameter: bw_brand, bw_model, bw_vin, bw_mileage, bw_services, bw_tire_storage, bw_date, bw_time, bw_replacement_car, bw_email, bw_first_name, bw_last_name, bw_phone, bw_address, bw_zip, bw_city, bw_country, bw_salutation, bw_message, bw_advisor, bw_step.
